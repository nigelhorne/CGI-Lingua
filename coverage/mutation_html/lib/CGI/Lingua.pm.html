 2379: =head1 LIMITATIONS
 2380: 
 2381: =over 4
 2382: 
 2383: =item * B<is_rtl() covers primary-script RTL languages only>
 2384: 
 2385: C<is_rtl()> returns true for the 10 ISO 639-1 codes whose overwhelmingly
 2386: dominant script is right-to-left.  Languages with script variants (e.g.
 2387: Azerbaijani C<az>, which uses Latin in modern Azerbaijan but Arabic in Iran)
 2388: are treated as LTR.  If you serve content in multiple scripts of the same
 2389: language, inspect the sublanguage or Accept-Language header directly.
 2390: 
 2391: =item * B<plural_category() uses embedded CLDR rules, not Locale::CLDR>
 2392: 
 2393: The embedded rules cover ~70 languages and truncate fractional C<$n> to an
 2394: integer.  For full CLDR v42 accuracy (including fractional forms and
 2395: languages not in the table) install and use C<Locale::CLDR> directly.
 2396: 
 2397: =item * B<Logger must be a blessed object>
 2398: 
 2399: The C<logger> parameter is documented as accepting a code ref, array ref, or
 2400: filename, but the current implementation calls C<< $logger->$level() >> and will
 2401: die on non-blessed values.  Wrap alternative logger types in a
 2402: C<Log::Abstraction> instance before passing them to C<new()>.
 2403: 
 2404: =item * B<es-419 sublanguage returns undef>
 2405: 
 2406: Three-part regional codes such as C<es-419> (Latin American Spanish) do not
 2407: resolve to a C<sublanguage()> value because ISO 3166-1 does not define '419'.
 2408: This is a known limitation of the Locale::Object layer.
 2409: 
 2410: =item * B<Whois lookups are slow and unreliable>
 2411: 
 2412: Without C<IP::Country>, C<Geo::IP>, or C<Geo::IPfree> installed, C<country()>
 2413: falls back to Whois queries against live RIPE/ARIN/IANA servers.  These can
 2414: time out under load.  Install at least one local geo-database module and enable
 2415: the CHI cache to avoid this.
 2416: 
 2417: =item * B<Private methods are accessible from outside the package>
 2418: 
 2419: The C<_*> methods use the naming convention for privacy but Perl does not enforce
 2420: it.  C<Sub::Private> or C<Sub::Protected> should be added once all white-box
 2421: tests (C<t/function.t>, C<t/extended_tests.t>) are updated to use the public API
 2422: exclusively.
 2423: 
 2424: =item * B<IPv4-mapped IPv6 addresses are normalised to IPv4>
 2425: 
 2426: C<REMOTE_ADDR> values in the form C<::ffff:a.b.c.d> (RFC 4291 section 2.5.5)
 2427: are silently rewritten to the embedded C<a.b.c.d> IPv4 address before any
 2428: geo-lookup.  This is correct for country detection purposes but means the raw
 2429: address string is not preserved in cache keys or log messages.
 2430: 
 2431: =item * B<EU country code is irresolvable (with one exception)>
 2432: 
 2433: IP addresses that Whois reports as country C<EU> are mapped to C<'Unknown'>
 2434: unless they fall within Baidu's known subnet (RT-86809).  There is no ISO
 2435: 3166-1 country code for the European Union.
 2436: 
 2437: =item * B<country() does not cache undef results>
 2438: 
 2439: When C<country()> cannot determine a country (private IPs, loopback,
 2440: unresolvable addresses), it returns C<undef> without storing the result.  A
 2441: second call on the same object repeats the full validation pipeline.  This is
 2442: intentional: C<country()> reads C<REMOTE_ADDR> at call time rather than at
 2443: construction time, so caching C<undef> would return a wrong answer if
 2444: C<REMOTE_ADDR> changes between calls.  In practice this is rarely a problem
 2445: because C<country()> is called once per request and CGI applications typically
 2446: create a fresh object per request.
